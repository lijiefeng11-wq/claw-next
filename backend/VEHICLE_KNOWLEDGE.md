# 商品资料与本地车型表

后台可按 `contracts/protocol.md` 接收协商后的 `goods_snapshot`。没有声明能力的客户端保持原行为；商品来源、时间、引用、字段和数量均校验。相同事件的原始请求保持幂等，不删字段重试，不影响 unknown。引用按现有契约校验类型、长度、唯一性与关联；摘要生成和平台编号脱敏仍由前台负责，后台不持有原始编号，无法逆向证明摘要来源。

车型表是可选的本机只读资料，不随代码发布。后台私有配置可以增加店铺到绝对目录的映射，例如：

```json
{"vehicle_knowledge":{"demo-shop":"/absolute/private/vehicle-table"}}
```

这里只展示增量字段；保留原有 shops、clients 和 model 配置。店铺必须已经登记。未配置的店铺不加载、不使用其他店铺的表。添加配置不会开启店铺或自动回复；修改配置和更新运行部署须单独获用户授权。

目录中每个 `.md` 文件应有一个 WPS_SYNC_START / WPS_SYNC_END 同步区块、记录编号，以及“原始列”下的两列表格。字段为版型、车系、车型、尺码、前挡/前窗/中窗/侧三/尾挡铁圈尺寸、前挡风上长/下长/高度、不透光专用。具体标签采用导出的原始中文列名。只读同步区块，不把手写备注纳入检索，不访问原表链接。忽略符号链接；限制文件数、目录项数和字节数；资料损坏时拒绝加载并返回不含原文、路径的错误类别。

目录在后台启动时读取一次；修改源表后需在另行授权的重启中重新加载。源文件不会写入、复制到仓库、作为静态资源公开或写入事件数据库。模型仅收到本店最新买家问题检索出的至多 5 条候选；不会获得源路径或链接。调用模型时适用当前主备配置，因此必要候选可能随该次模型请求提交给所配置的模型服务。

检索支持大小写、空白规整，显式斜线/顿号车型别名，以及移除年份标签后的候选匹配。不做近似拼写、别名猜测或自动年份/版型选择。同一问题里提到多种车型时保留所有命中，不按名字长短替买家选车。无结果不代表不适配；多结果必须澄清。即使只有一条候选，也不能据此认定当前商品适配：还要核对年份、款型、窗位和具体商品。空白尺寸保持未知，不补单位或推断版型含义。材质、安装、退换货、现价、库存等仍须单独的有效店铺规则。

实现与虚构数据测试通过不等于真实业务验收。保持仅观察，完成商品和车型映射及业务规则确认后，再另行安排验收和部署。
