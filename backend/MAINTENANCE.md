# 本地维护与建议查看

前台“仅观察”或“人工接管”模式仍可把满足身份、租约、历史与时限要求的新消息交给后台规则 / 模型判断，但发送前会拦住 claim。后台店铺设置须允许判断；关闭后台开关得到的是不处理结果。管理页“处理记录”展示已有判断和建议正文；尚未领取的回复标为建议，店主须人工核对。管理页不替用户切换客户端模式，也不开启标星或转人工能力。不要把读取记录当作真实平台验收。

## SQLite 备份

服务启动后，独立后台线程检查 `data_dir/backups/`：无有效近期快照时使用 SQLite backup API 从 `claw-next.sqlite3` 创建一致性快照，随后每天检查备份。使用独立只读连接，包含已提交 WAL 内容，不占用 Store 的全局锁。快照通过 integrity_check 后才原子发布并清理旧快照，保留最近 7 份；其他文件不清理。失败保留旧份，60 秒后重试，不停止判断服务。

POSIX 上目录权限 0700，快照 0600；Windows 的实际文件访问权限由当前用户目录 ACL 管理，不能把 chmod 数值当作 Windows 权限证明。快照包含业务记录及保存的设置，仅留本机，不提供下载接口，不提交 Git。备份仅涵盖该后台 SQLite，不包含客户端登录资料、独立管理员认证库、模型密钥或配置文件；不能当作整机回滚包。同盘备份也不能防磁盘整体损坏。

恢复只能在明确安排的维护窗口进行：停止本项目后台、先另存当前数据库及 WAL/SHM、核对快照完整性和时间，再在隔离副本验证。旧快照可能含历史未结束尝试，恢复后必须沿用 unknown 不重试规则，不自动重新领取、补发或清除结果。本次实现不自动恢复或操作生产数据。

## 管理页提醒

管理页打开且登录时，每 5 秒的既有状态轮询同时核对管理员概览：后台连接未确认、判断线程停止、任一店铺连续至少 3 次模型判断失败、unknown 记录或备份失败时显示本地横幅。页面关闭、退出登录或设备睡眠时不提供系统通知，也不调用外部通知服务。网络错误只表示连接未确认，不证明后台已停止。

模型失败计数按店铺隔离，仅在本次后台进程中累计；明确的模型成功（包括语义规则命中）清除该店铺的连续失败，规则直接命中或取消 / 过期不证明模型成功。计数在平台动作 fallback 处理之前记录，避免收藏 / 转人工策略掩盖模型异常。主模型失败但备用模型成功视为本次判断成功。unknown 提醒来自现存记录，不修改、不重试这些记录。

`GET /api/v1/admin/summary` 保留 `counts` / `protocol_version`，增加仅管理员可读的 `maintenance` 元数据：`model_failures`（按店铺计数）、`worker_alive`（布尔）、`backup`（`status: idle|ok|error`、`last_success: Unix 秒或 null`）。不返回本机路径、异常原文、模型输出、密钥或备份内容；客户端通信契约不变。未登录、客户端令牌和首次密码未修改的管理员都不能读取该接口。

服务发布、客户端更新与真实平台功能仍须分别验收。本次维护功能合入不等于已部署或已启用能力。
